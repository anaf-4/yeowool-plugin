# 마을 연합 시스템 — 2단계(연합 채팅) 설계

## 배경

마을 연합 4단계 구상 중 2단계. 1단계(기반, `yeowool-federation`)는 완료됨 — 설계는 `2026-09-23-village-federation-foundation-design.md` 참고. 이 문서는 연합원끼리만 보이는 크로스서버 채팅만 다룬다. 3단계(연합 은행/상점/레벨업), 4단계(랭킹/이벤트)는 각각 별도 스펙.

## 목표

- 같은 연합 소속 토지의 **소유주 + 주민 전원**이 서로에게만 보이는 채팅을 주고받는다.
- lobby/town/wild 어느 서버에 있든 서로의 메시지가 보인다.
- 두 가지 사용법을 모두 지원한다 (기존 `/마을`·`/채널 마을`과 같은 감각):
  - `/연합채팅 <메시지>` — 한 번만 연합 채팅으로 보냄
  - `/연합채팅` (인자 없음) — 연합 채팅 모드 켜기/끄기. 켜져 있으면 평소 채팅이 전부 연합 채팅으로 감

## 비목표

- 기존 `/채널`(yeowool-community)에 "연합"을 추가하는 것 — community 모듈이 연합 테이블에 의존하게 되므로 하지 않음 (연합 채팅 모드는 `/채널`과 독립된 토글).
- 연합 채팅 기록 저장/조회, 연합 공지 — 요청받지 않음.

## 아키텍처

두 모듈만 바뀐다. `yeowool-community`는 건드리지 않는다.

### 1. `yeowool-proxy` — 범용 "지정 수신자 전달" 채널

- 새 플러그인 메시징 채널 `yeowool:targeted`.
- 페이로드: `int 수신자수`, `UTF 수신자UUID` × 수신자수, `UTF 메시지(Adventure Component JSON)`.
- 프록시는 목록의 UUID 중 **현재 프록시에 접속 중인 플레이어**에게 메시지를 그대로 전달한다. DB도 서버 이름도 모른다.
- 보내는 서버가 자기 서버에 접속 중인 수신자는 목록에서 **미리 빼고** 보내므로, 프록시는 중복 전달을 신경 쓸 필요가 없다 (기존 `yeowool:chat`처럼 "보낸 서버 이름"을 싣지 않아도 됨).
- 연합 전용이 아닌 범용 채널이라 4단계(연합 이벤트 알림 등)에서도 재사용한다.

### 2. `yeowool-federation` — 연합 채팅

**소속 연합 판정** (플레이어 → 연합, DB 조회 1회):
- 플레이어가 **소유한** 토지가 연합 소속이면 그 연합.
- 아니면 **주민(`yw_land_members`)으로 속한** 토지들의 연합 중 연합 이름순으로 첫 번째 (여러 토지의 주민이라 연합이 둘 이상인 드문 경우를 결정적으로 처리하기 위함).
- 둘 다 없으면 "소속 연합 없음".

**수신자 계산** (메시지 1건당 DB 조회 1회): 그 연합에 속한 모든 토지의 소유주(`yw_lands.owner_uuid`)와 주민(`yw_land_members.member_uuid`)의 UUID 합집합.

**전달**:
1. 이 서버에 접속 중인 수신자에게 직접 전송 + 콘솔에도 출력.
2. 나머지 UUID(이 서버에 없는 사람)가 있으면 보낸 플레이어의 연결로 `yeowool:targeted` 페이로드를 프록시에 전송.

**출력 형식**: `[연합] <표시이름>: <메시지>` — `[연합]`은 초록 계열(기존 `[마을]` 태그와 구분되는 색). 표시이름은 `player.playerListName()`을 그대로 사용 — yeowool-community의 `PlayerIdentityService`가 랭크 아이콘/칭호/한글 닉네임을 합쳐서 이미 넣어두는 값이라, community 모듈에 의존하지 않고도 다른 채팅과 같은 이름 표시가 된다.

**연합 채팅 모드 (토글)**:
- 상태는 플레이어 설정(`core.playerData().getOnline(uuid).setSetting("federation.chat-mode", ...)`)에 저장 — 재접속/서버 이동 후에도 유지.
- 새 채팅 리스너가 `AsyncChatEvent`를 `EventPriority.LOW`로 받는다 (community의 `ChatListener`는 `NORMAL` + `ignoreCancelled = true`라, 여기서 취소한 채팅은 자동으로 무시됨 — community 수정 불필요).
- 모드가 켜진 플레이어의 채팅:
  - 소속 연합이 **있으면** → 이벤트 취소 후 연합 채팅으로 전송.
  - 소속 연합이 **없으면**(그 사이 탈퇴/추방/폐쇄/토지 삭제) → 모드를 자동으로 끄고 안내 메시지를 보낸 뒤, 이벤트를 취소하지 **않아서** 그 채팅은 평소 채널로 정상 전송된다.
- 모드를 켜고 끌 때 "`/연합채팅`을 다시 입력하면 해제, 켜져 있는 동안은 `/채널` 설정보다 연합 채팅이 우선" 이라고 안내한다.

**음소거·도배 방지** (한 번 보내기와 모드 채팅 공통):
- `core.punishments().activeMute(uuid)`로 음소거 중이면 거부 (community와 같은 방식).
- 연합 채팅 전용 쿨다운 `chat.cooldown-ms` (federation `config.yml`, 기본 1500 — community의 `chat.cooldown-ms` 기본값과 동일).

**스레드**: `AsyncChatEvent`는 이미 비동기 스레드라 거기서 DB 조회를 해도 된다. `/연합채팅` 명령어는 메인 스레드에서 실행되므로 기존 `FederationCommand`와 같은 방식으로 federation 전용 executor에서 조회 후 전송한다. 플레이어에게 메시지를 보내는 것(`Player#sendMessage`)은 Paper에서 스레드 안전.

## 에러 처리

- 소속 연합 없음 → `federation.chat-no-federation` 안내.
- `/연합채팅` 인자 없이 토글 켜기 시도했는데 소속 연합 없음 → 켜지 않고 같은 안내.
- DB 오류 → 스택트레이스 포함 로그(`Level.SEVERE`), 플레이어에게는 메시지를 보내지 않음 (1단계와 같은 관례).
- 프록시가 꺼져 있거나 페이로드 전송 실패 → 같은 서버 수신자에게는 이미 전달됐으므로 경고 로그만 남김.

## 도움말

`help.yml`의 **마을연합**, **채팅** 카테고리에 `/연합채팅 [메시지]`를 추가.

## 테스트

새 순수 로직이 거의 없음(수신자 계산·소속 판정은 SQL, 전달은 Bukkit/프록시). 1단계와 같은 관례대로:
- 빌드 + 서버 시작 시 에러 없음 확인.
- 인게임: 서로 다른 서버에 있는 같은 연합원 A(소유주)·B(주민)가 `/연합채팅 안녕`으로 서로 메시지를 받는지, 연합이 없는 C에게는 안 보이는지, 모드 토글 후 일반 채팅이 연합으로 가는지, 탈퇴 후 모드가 자동으로 꺼지고 일반 채팅으로 돌아가는지 확인.

- `yeowool-core` jar(help.yml 변경) → lobby/town/wild.
