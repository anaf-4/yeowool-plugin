# 서버 공동 목표 (기부 프로젝트) 설계

## 목표
세 서버가 함께 아이템을 기부해 주간 목표를 채우면 전 서버 버프와 보상을 받는다. 남는 재료를 소모시키고 서버를 하나로 묶는다.

## 모듈
`yeowool-life` (서버 버프는 기존 깜짝 이벤트 `surprise/*`의 버프 적용 방식 `LifeBoosts`를 재사용).

## 프로젝트
- **매주 월요일 00:00**(서버 시간) 새 프로젝트 시작, 다음 월요일 00:00 마감 (설정 `donation.start-day`, `donation.duration-days`).
- 프로젝트 = 이름 + 목표 품목 1~5개(아이템 + 목표 수량). 예: "마을 창고 채우기: 밀 50,000 · 철 주괴 5,000 · 참나무 원목 20,000".
- **목표 정하기**: 운영진이 게임 안에서 다음 주 프로젝트를 예약(`/기부관리 예약` → GUI에서 품목 아이템을 올리고 수량 입력). 예약이 없으면 설정의 **후보 목록**(`donation.pool`: 이름 + 품목들)에서 무작위로 고른다.
- 품목은 **아이템 비교**: 바닐라 재료는 종류(Material)로, ItemsAdder 아이템은 네임스페이스 id로 판정(이름·설명 붙은 아이템은 받지 않음 — 이름 바꾼 아이템 방지).

## 기부
- `/기부`로 창 열기 (어느 서버에서나): 품목별 진행도(바), 내 기여량, 남은 시간. 품목 칸을 클릭하면 인벤토리의 해당 아이템을 **남은 수량까지** 가져간다(1묶음/전부 선택).
- 처리 순서(교환소·주문과 같은 안전 방식): 메인에서 개수 확인 → 작업 스레드에서 행 잠금 후 남은 수량만큼 진행도 증가 → 메인에서 아이템 제거(사라졌으면 진행도 되돌림).
- 기부마다 **기부 점수** = 품목별 설정 점수 × 개수 (예: 밀 1점, 철 주괴 10점). 순위는 점수로.
- 진행도 보스바: `/기부` 창을 열었거나 기부한 사람에게 1분간 표시. 세 서버 공지: 시작·50%·90%·품목 하나 완료·전체 달성.

## 달성 보상 (모든 품목 완료 순간 한 번, 세 서버 중 한 곳만 정산)
- **전 서버 버프 24시간**: 프로젝트마다 하나(설정/예약 시 선택, 기본 순환): 토지 경험치 2배 / 작물 수확량 2배 / 직업 경험치 2배 / 보물지도 발견 3배 — 깜짝 이벤트와 같은 버프 적용 방식(수동 버프와 겹치면 큰 쪽).
- 기부 점수가 있는 참여자 전원: 별조각 5 (기여 점수 하위 제한 `donation.min-score` 이상).
- 기여도 1·2·3위: 별조각 +30/+20/+10, 1위 칭호 명령어(설정 `donation.top-commands`, 콘솔 실행 `{player}`).
- 마감까지 못 채우면 실패 공지, 기부한 아이템은 돌려주지 않음(대신 기부 즉시 품목별 소액 온 지급: `donation.money-per-point` 기본 2온/점 — 실패해도 헛수고 아님).

## 데이터
- `yw_donation_project(id, name, starts_at, ends_at, status ACTIVE/DONE/FAILED, buff, settled)`, `yw_donation_goal(project_id, slot, item_key, display_item, target, progress, points)`, `yw_donation_contrib(project_id, uuid, name, points)`, 예약 `yw_donation_schedule(...)`, 공지 테이블.
- 시작·마감·정산은 1분마다 세 서버가 점검하되 조건부 UPDATE/유니크 키로 한 서버만 처리.

## 명령
- `/기부` (모두), `/기부 순위`.
- `/기부관리` (op): `예약`(다음 프로젝트 편집 GUI), `시작 [후보이름]`(즉시 시작, 진행 중이면 거부), `종료`(실패 처리), `리로드`.

## 테스트
JUnit: 주간 시작·마감 시각 계산, 후보 무작위 선택, 기부량 클램프, 점수·순위, 달성 판정.
